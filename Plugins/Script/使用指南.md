# C# Plan Script 使用指南

> 文档版本：1.0  
> 更新日期：2026-10-24  
> 适用代码版本：当前仓库 OpenTAP 9.34.0，`Tap.Plugins.Script`（.NET 8）

## 1. 功能简介

`Tap.Plugins.Script` 使用 Roslyn 编译并运行 C# 脚本。脚本采用 C# 顶级语句写法，不需要声明 `class` 或 `Main`，可以使用 `async` / `await`。

脚本有两种运行方式：

1. 在 OpenTAP 测试计划中添加 `Script` 步骤。适合将少量自定义逻辑放进可编辑、可保存、可查看结果的 `.TapPlan`。
2. 通过 `tap script <文件.csx>` 独立运行脚本。适合命令行自动化或脚本工具。

脚本以受信任的 C# 代码运行，**没有沙箱隔离**。只运行来源可信的脚本。

## 2. 第一个脚本

创建 `hello.csx`：

```csharp
Log.Info("脚本开始");

var voltage = 15.0;
Log.Info($"电压测量值：{voltage} V");

Assert.InRange(voltage, 14.25, 15.75, "电压超出范围");
Results.Publish("电压测量", voltage, "V");
Verdict = Verdict.Pass;
```

顶级语句可以直接使用以下全局对象：

| 对象 | 用途 |
| --- | --- |
| `Log` | 输出 Debug、Info、Warning、Error 日志 |
| `Assert` | 执行条件、相等性和数值范围断言 |
| `CancellationToken` | 检查用户是否请求中止 |
| `Instruments` | 按名称获取已配置的仪器资源 |
| `Duts` | 按名称获取已配置的 DUT 资源 |
| `Steps` | 将一个 `TestStep` 放入临时计划并执行 |
| `Results` | 发布脚本结果；计划步骤模式下会转发到结果系统 |
| `Verdict` | 读写脚本判定 |

编译时默认导入 `System`、`System.Collections.Generic`、`System.IO`、`System.Linq`、`System.Threading`、`System.Threading.Tasks`、`OpenTap` 和 `Tap.Plugins.Script`。其他插件命名空间可在脚本开头使用 `using` 引入。

## 3. 在 WPF 测试计划中使用

1. 打开 WPF 编辑器，使用步骤库添加 **Script** 步骤。
2. 选中该步骤，在右侧属性中填写 **Inline Source**，或在 **Script File** 中选择 `.csx` 文件。
3. 如果两个属性都填写，**Script File 优先**，Inline Source 不会执行。
4. 保存计划为 `.TapPlan`，然后点击 **Run** 执行。

脚本较长或需要版本管理时，推荐保存为单独的 `.csx` 文件并通过 **Script File** 引用。计划保存的是脚本文件路径，不会把外部脚本内容嵌入计划。

计划步骤模式下：

- 脚本成功结束且未设置 `Verdict` 时，脚本步骤默认为 `Pass`。
- 设置全局 `Verdict`，或让脚本最后一个表达式返回一个 `Verdict`，可以明确指定判定。
- `Assert` 断言失败会将脚本步骤判为 `Fail`。
- 其他未处理异常会作为步骤执行错误记录。
- `CancellationToken` 会随计划 Abort 取消。
- `Results.Publish` 发布的数据会进入计划结果系统。

## 4. 使用仪器和 DUT

`Instruments.Get<T>(name)` 和 `Duts.Get<T>(name)` 会按名称查找当前设置中的资源。资源必须已经在 OpenTAP 设置中配置，且名称和类型要匹配。

以下示例通过已安装的 UDS 插件调用 CAN 仪器：

```csharp
using Tap.Plugins.Uds;

var can = Instruments.Get<CanInstrument>("CANFD_ECU");

var step = new CanUdsRequestStep
{
    Name = "读取 ECU 识别码",
    Instrument = can,
    UdsPayload = "22 F1 90",
    ExpectedPrefix = "62 F1 90",
    TimeoutMs = 5000
};

var execution = await Steps.RunAsync(step, CancellationToken);
Log.Info($"UDS 步骤判定：{execution.Verdict}");
Results.Publish("ECU 识别码", step.Response, step.MeasuredValue);

if (execution.Verdict != Verdict.Pass)
    Verdict = execution.Verdict;
```

`Steps.RunAsync` 会把传入的步骤放入一个单步骤临时计划中运行，并返回 `ScriptStepResult`，其中包含 `Verdict` 和 `TestStepRun`。这个调用**不会将步骤添加到当前计划的步骤树中**；如果希望步骤在编辑器中作为独立步骤显示、配置和重复运行，应直接把相应步骤加入计划，而不是通过脚本临时运行。

插件程序集在脚本编译时会自动作为引用加载；但对应插件仍须安装或被当前 OpenTAP 进程加载。仪器和 DUT 仍需在设置中配置。

## 5. 日志、断言、结果与判定

### 日志

```csharp
Log.Debug("调试信息");
Log.Info("测试开始");
Log.Warning("发现可恢复的问题");
Log.Error("发生错误");
```

日志方法支持复合格式参数：

```csharp
Log.Info("测量值：{0} {1}", 12.4, "V");
```

### 断言

```csharp
Assert.True(isConnected, "仪器未连接");
Assert.False(hasAlarm, "设备报告故障");
Assert.Equal("PASS", deviceState, "设备状态不正确");
Assert.InRange(measuredValue, 4.8, 5.2, "电压超出规格");
```

也可以主动失败：

```csharp
Assert.Fail("当前条件不允许继续测试");
```

### 发布结果

```csharp
Results.Publish("电源测量", 12.4, "V", "输出端 1");
```

在计划步骤模式下，这些值会作为脚本步骤结果发布。独立 CLI 模式创建的 `ScriptResults` 当前没有连接 OpenTAP 结果监听器，因此不要依赖它将结果写入结果数据库或 CSV；独立模式下可使用日志、文件输出或由调用脚本显式处理数据。

### Verdict

建议在脚本末尾明确设置判定：

```csharp
Verdict = Verdict.Pass;
```

可用判定包括 `Pass`、`Inconclusive`、`Fail`、`Aborted` 和 `Error`。例如：

```csharp
if (measuredValue < lowerLimit || measuredValue > upperLimit)
    Verdict = Verdict.Fail;
else
    Verdict = Verdict.Pass;
```

计划步骤模式下，没有设置判定时成功执行默认为 Pass。独立 CLI 模式中，返回的 `Verdict` 或全局 `Verdict` 达到 Fail 或更严重时，命令返回非零退出码。CLI 对异常也返回非零退出码；用户取消时返回专用取消码。

## 6. 响应中止与异步操作

长循环中定期检查取消令牌：

```csharp
for (var index = 0; index < 100; index++)
{
    CancellationToken.ThrowIfCancellationRequested();
    Log.Info($"处理项目 {index + 1}");
    await Task.Delay(100, CancellationToken);
}
```

避免使用不接受取消令牌的长时间阻塞操作，否则用户点击 Abort 后，脚本可能无法及时停止。

## 7. 独立命令行运行

使用仓库构建输出运行示例：

```powershell
.\bin\Debug\tap.exe script .\Plugins\Script\Examples\basic.csx
```

脚本参数是 `.csx` 文件路径。独立运行时，`Instruments` 和 `Duts` 从当前 OpenTAP 设置加载。脚本若使用插件类型，运行环境中必须安装或加载相应插件。

退出码约定：成功为 `0`；文件不存在、编译失败、断言或运行异常为非零；取消为 `3`。脚本如果要报告测试失败，应设置 `Verdict = Verdict.Fail` 或返回一个 `Verdict` 值。

## 9. 常见问题

| 现象 | 检查项 |
| --- | --- |
| 找不到 `tap script` 命令 | 确认 `Tap.Plugins.Script` 已安装，并使用该 OpenTAP 安装目录下的 `tap.exe` |
| 脚本编译时报类型或命名空间不存在 | 确认相关插件已安装并加载；确认脚本中有需要的 `using` |
| `Instruments.Get<T>` 报资源不存在 | 检查仪器设置中的资源名称和类型是否与脚本匹配 |
| 计划步骤总是执行外部文件 | 检查 **Script File** 是否非空；非空时它优先于 Inline Source |
| 点击 Abort 后脚本仍运行 | 在循环中检查 `CancellationToken`，并为异步等待传入取消令牌 |
| 计划步骤显示 Fail | 查看断言消息和脚本日志；若是断言失败，检查输入值和范围 |

## 10. 安全注意事项

C# 脚本不受沙箱限制，可以访问当前进程权限允许的文件、网络、环境变量和其他资源。执行前应审查脚本来源、依赖插件和外部输入，不要运行不可信 `.csx` 文件。
